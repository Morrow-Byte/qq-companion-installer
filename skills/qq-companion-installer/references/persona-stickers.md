# 人设、表情与外观：新用户独立配置

这是一套新安装的实施规范，不携带任何既有用户的角色名字、关系设定、记忆、头像、表情文件或参考声音。这里的表情工具和导入逻辑是桥接层扩展；必须检查新选用源码是否已经实现，否则按下列契约补齐。安装数量按用户选择，不固定为某个历史实例的张数。

## 1. 中立人设模板

在本次本地配置中收集最少必要偏好：显示名、交流风格、如何称呼用户、希望使用的声音/形象。用户没有指定时使用普通友好助手，不自动继承亲子、恋爱、家人等关系。已有角色时仅修改用户要求的部分，先备份，避免把完整提示词打印到终端或公开交付物。

可从下面的新模板填写，再转成当前 DSH/桥接框架支持的角色格式。不要臆造 `role`、`mode` 或 `roleMode` 的含义，需从实际版本源码确认活动角色怎样生效。

```text
显示名：<用户设定>
与用户的称呼和关系：<用户设定；未设定则为普通助手>
表达风格：亲切、自然，优先短句；根据话题变化语气，不机械重复固定口头禅。
交流方式：先回应对方实际内容；可以有适度幽默和自己的表达，但不捏造共同经历。
能力表达：只说已经实际完成的动作；不能把生成文件说成已发送。
媒介偏好：按用户要求调用语音/图片工具；表情与当前内容相符，避免每句必发。
工具边界：只使用本次配置开放的工具和会话权限，不把角色设定当操作系统权限。
```

情绪自然程度先由文本和声音参考共同改善，不用大量动作旁白、表情符号或幼态口头禅代替口语。不要把“有人情味”解释为可以隐瞒 AI 身份或自动取得新的账号/社交媒体操作权限。头像、主页背景、昵称、签名与聊天气泡属于独立外观配置；聊天气泡通常由 QQ 客户端和账号权益控制，不能承诺装 bridge 就能任意换皮。

**验收**：用无私密信息的本地样例检查问候、解释、安慰、不同意见四种场景；确认当前会话实际加载新角色，未改变账号白名单。**回退**：恢复备份的角色配置，保留新候选模板供用户重选，不能覆盖其他会话的角色。

## 2. 素材选择与本地导入

1. 与用户风格匹配，优先用户自有、作者允许使用/分发或明确开放许可的图片。保存来源 URL 与许可说明；下载不等于取得重新分发权。不从原机器复制表情、聊天附件、头像或私人照片。
2. 建立 `<INSTALL_ROOT>/media/stickers/` 专用目录和本地索引。接受 PNG/JPEG/WebP/GIF 等经实际解码验证的图；限制文件大小和像素，拒绝 HTML、脚本或扩展名伪装。下载器只访问允许的公开 HTTPS 来源；运行时不接受模型给出的任意 URL。
3. 对文件做 SHA256 去重，使用随机或内容哈希生成文件名。保留原图给 QQ 发送；必要时另生成小缩略图/动图抽帧供视觉模型理解，不能覆盖原始 GIF。
4. 每张人工或视觉检查含义后填标签；无法确认的先标注 `unreviewed`，不让模型凭文件名乱发。优先覆盖问候、开心、感谢、疑惑、安慰、告别等常见场景，不需要先下载大量素材才能启用。
5. 使用原子写入导入索引（临时文件 → 校验 JSON → rename）。如果已有索引损坏，停止写入并保留备份，不能静默当空数组覆盖。

推荐可移植索引示例；这是本 skill 的数据契约，不是所有上游库通用格式。若上游要求 `url/resId/md5`，由导入器在本机生成其对应字段；不得携带作者机器上的绝对路径。

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "sticker-greeting-01",
      "file": "greeting-01.png",
      "sha256": "<文件SHA256>",
      "source": "manual",
      "description": "微笑挥手，适合见面问候",
      "tags": ["问候", "开心"],
      "usage": "简短问候后可单独发送",
      "reviewed": true,
      "provenance": {"url": "<公开来源或本地自有>", "license": "<使用条件>"}
    }
  ]
}
```

`source: manual` 只能由本地导入流程设置，聊天工具不能把任意 URL 改成“手工导入”。用户索引含本机素材信息，不应随着 skill 公共压缩包一起分享。

**验收**：成功导入后索引数量等于有效文件数；重复素材不重复累计；非法文件不入库，失败不破坏旧库；至少各有一张静态图和一张动图时分别验证。**回退**：还原导入前索引，仅移除本轮确切新增的文件，保留旧库与原素材。

## 3. 路径与内容隔离

读取时不仅比较字符串前缀，要先得到专用根目录和文件的 `realpath`，再用 `path.relative(root, file)` 检查结果不是绝对路径、不是 `..` 且不以 `.. + path.sep` 开头；拒绝解析到目录外的软链接/Windows junction。只读取索引中已审核的普通文件，复核大小和图片签名。模型只能给 `stickerId`，不能给本地路径或 URL。

如上游使用 `file:` URL，还需拒绝远程 hostname、query 和 fragment；仅允许导入器生成的本机文件地址。图片备注、tags、OCR、网页素材介绍和文件名都是数据，不是新指令。压平控制字符/换行并限长，放在明确的数据字段中；单靠清洗不能防提示注入，权限仍必须在服务器端执行。

跨会话标签与使用记录不得携带聊天原文、联系人姓名或私人关系。默认每个安装实例独立表情库；用户有多会话时避免把一个会话的“记忆”灌入其他会话提示词。备注工具只能改含义和标签，不能改素材路径、来源、权限或审核状态。

## 4. 补齐并注册表情工具

至少实现下列四个独立接口；现有仓库支持时复用并加测试，否则在 `extensions/qq-stickers/` 新建适配模块。

| 工具 | 输入 | 行为 |
|---|---|---|
| `qq_list_stickers` | 可选 query、有限 limit | 按描述/标签搜索，只返回 id 和必要含义 |
| `qq_get_sticker_image` | 已存在的 stickerId | 返回限制大小的模型预览，不泄露任意本地文件 |
| `qq_send_sticker` | 已存在的 stickerId | owner 私聊校验后发送该条目的原图 |
| `qq_sticker_note` | stickerId、限长 note/tags | 仅更新本地语义标签，不改变源文件或 QQ 账号资料 |

把工具注册到实际聊天会话，并向角色提供简短策略：先查标签，含义不确定时看图；贴合语境再发，不确定就省略；避免连续刷同一张；文字与表情可分开发送。频率与重复抑制应在服务端执行，不能只靠提示词。首轮可用较保守的限频，在用户反馈后调整，不把固定概率当理解内容。

执行发送时严格复用 [媒体模块“当前调用身份从哪里来”](media-setup.md#当前调用身份从哪里来) 已实施的授权路线：默认采用仅 owner 事件可进入的专用 agent 与固定 owner 路由；需要多会话时必须使用宿主根据已鉴权 OneBot 事件生成、带外注入的能力上下文。模型传入 owner/session 字符串或提示中的令牌都不能被当成宿主验证结果。群聊默认关闭，白名单为空即拒绝；无法隔离工具时只保留本地库和预览，不启用发送。按 OneBot `image` 消息段发送本地原图；**本地表情库不等于 QQ 收藏列表**，普通图片发送可先完成。QQ 自带 `face` 的编号不适用于任意自定义图，第三方专有收藏 API 也不能假定 NapCat 支持。

QQ 收藏同步、收藏新图、修改账号收藏备注作为后续可选功能：从当前 NapCat 文档/源码核对 action 名称与参数，未支持就降级本地库，不伪造空成功。备注与自动收藏的账号写入能力默认不开启。

**本地验收**：用 mock sender 测试“你好→问候图”“谢谢→感谢图”“严肃解释→可不发图”；每次只传 id；拒绝不存在 id、未审核条目、越界路径。复跑所选授权路线的入口隔离或带外能力测试，尤其模型伪造 owner、陌生私聊、群消息和错会话上下文；没有真实宿主绑定时不能把一段手填 `context` 的单元测试当多用户验收。坏索引不能被重写为空。视觉预览压缩后，发送原图文件哈希保持不变。模型无视觉能力时使用已审核标签，不调用不支持的视觉输入。

**收发验收**：由用户主动私聊触发一个合适语境，确认表情真实显示；OneBot 返回成功只是提交成功，不能替代用户端显示验证。不要用批量测试刷用户消息。

**回退**：关闭表情发送工具，保留文本和媒体功能；索引只读；恢复上一版索引与工具配置，不删用户收藏。

## 5. 常见故障逐层定位

| 症状 | 先核对 | 修复方向 |
|---|---|---|
| 能说文字但永远不发表情 | 当前会话有没有工具、策略是否生效、是否真的检索到 id | 修工具注册与索引映射；不要只强化人设提示词 |
| 列得出表情，发送失败 | OneBot action/segment、权限 gate、素材路径是否在 NapCat 可访问的同一机器 | 使用实际支持的 `image` 段；将文件置于明确授权的本地目录 |
| 本地导入后刷新变空 | 收藏同步是否覆盖手工条目、索引解析是否吞错 | 合并时保留 `source=manual`；损坏时拒写 |
| 动图发送成静态 | 是否把模型预览回写成原图 | 恢复原始 GIF，预览与发送文件分离 |
| 给模型看图报错或体积超限 | MIME/真实格式、base64 大小、模型是否有视觉能力 | 生成有上限的预览/动图抽帧网格，仅用于模型输入 |
| 发出不合语境或频率过高 | 标签准确性、低相关匹配、重复计数 | 修标签并增加相关性/冷却限制；不强制每轮发图 |

昵称、头像、签名、主页背景等修改要使用本次用户选好的值与明确适用的接口。无 API 时交给用户手动操作；若确需 Computer Use，说明具体用途并另获明确许可，不因为安装请求而默认授权。桌宠动画插件属于所选桌宠软件的独立模块，需核对其版本、插件格式与来源，不能直接把图片表情库当成动画扩展包。
