# 排障与恢复

先做只读诊断，再改动最小范围。不得公开打印配置、登录凭据、QQ 用户资料、会话内容或日志尾部。只在内存中筛选状态码、错误类型、耗时、进程身份和所需配置字段，分享报告使用 `<BOT_QQ>`、`<OWNER_QQ>`、`<INSTALL_ROOT>`。

## 核心连接

| 症状 | 先核验 | 处理与成功条件 |
| --- | --- | --- |
| 页面显示已登录但机器人无回复 | WebUI 认证、QQ `isLogin/coreReady`、OneBot `online` 是否分开判断 | 对照 `get_login_info` 在本机检查账号，要求 QQ 核心在线和 bridge 事件链都成功 |
| 二维码附件看不到 | 实际是 PNG 还是仅登录 URL；文件是否新生成；附件能力是否可用 | 用本地 QR 库编码返回 URL，换新文件名，提供可手动打开的 PNG；禁止上传在线二维码服务 |
| 扫码后卡初始化 | 网关所需 QQ 版本、对应账号的其他 PC 登录实例、核心状态、WebUI API 错误类型 | 让用户手动退出冲突实例，或在明确授权后仅停止已识别的本项目进程；不要批量杀 QQ/node；重新启动后提供新二维码 |
| HTTP 426 | `snowluma.httpUrl` 是否填成 WS 端口 | HTTP 和 WS 使用各自端口；只读 action 返回 `retcode=0` 后再测消息 |
| OneBot 401 / WS 断线 | HTTP 与 WS token 是否一致、URL/端口、网关实际账户 | 显式同步本次部署的 token；关闭读取 SnowLuma schema 的自动发现；不要回退为空 token |
| WebUI 401 | 是否把 OneBot token 当作 WebUI Credential | 按版本正确完成 WebUI auth，Credential 过期才刷新；不把 Credential 写进共享日志 |
| 控制台 401/403 | `x-console-token`、回环 Host、Origin、管理/agent 通道区别 | 使用合法本机地址和管理 token；不关闭 Host/Origin/令牌检查 |
| QQ 在线但桥接不响应 | `allow.private`、`allow.groups`、`allowAllWhenEmpty`、mode、mute、sleep 状态 | 精确添加本次允许账号；私聊部署保持群列表空、`allowAllWhenEmpty=false`；不要用开放全部来排障 |
| 文本到达但 DSH 不工作 | `dshReady`、模型授权、provider/model ID、Cookie/API 代际、preset 注册 | 使用相容版本并重跑相应 setup；先备份 DSH profile，不擦除整个用户数据目录 |
| WS 连通却无入站消息 | 心跳、`messagePostFormat`、网关是否上报、自消息过滤、账户在线状态 | 使用 `array` 消息段；只读 WS action 回包仅证明 API 通，不证明消息上报；最终由用户主动发一条测试消息 |
| 重启出现重复回复 | 多个 bridge/NapCat 实例、重复 WS 接入、同会话并发锁 | 对比 PID 的路径/命令行，停止本项目重复实例；保留单一消费实例和会话序列化 |

## 语音、图片、表情

| 症状 | 检查顺序 | 不能做的“修复” |
| --- | --- | --- |
| 本地有音频，QQ 发不出去 | 文件格式与实际编码、采样率/时长/大小、NapCat 支持的 record/SILK 转换接口、目标白名单、工具权限 | 把 WAV 改扩展名成 SILK；绕过媒体根目录；仅凭磁盘文件存在报成功 |
| 语音像念稿或只变尖 | 当前模型、参考音频、文本标点/停顿、语速、情绪参考、转换链 | 反复提高音高冒充自然甜美；把 TTS 音节拉长拼成歌声 |
| 画图服务正常但 AI 不调用 | 工具是否注册并进入当前 preset；schema、参数、会话授权是否可用 | 只启动 ComfyUI 就说集成完成；给聊天 agent 完整文件系统/终端 |
| 图片生成后发送失败 | ComfyUI job 结果、输出目录、图片魔数、大小/像素、OneBot image 段格式 | 把错误 JSON/HTML 当图片；让网关任意抓取不可信 URL |
| QQ 收藏表情为空 | 账号是否真的有收藏、该 NapCat 版本是否支持对应扩展动作 | 认为磁盘上的文件已自动加入 QQ 账号收藏 |
| 本地表情找不到或无法发送 | 本地索引加载、路径限制、图片格式、标签、`list/get/send` 三类工具是否同时可用 | 把绝对路径传给不受限模型；取消 SSRF 检查；把远程404当作“模型不喜欢发” |
| 表情与话题不搭 | 标签是否真实描述内容、是否支持先看图、人格提示是否要求强行配图 | 固定每几句话必须发一张；误把标签中的文字当指令 |

表情可用本地受限目录加索引实现，不必伪装成账号收藏。图片读取必须先验证路径位于库根目录，防止 `..`、绝对路径覆盖和符号链接越界，再验证类型、大小/像素；对外发送统一使用已读取的合规图片 bytes/base64，避免把内部路径或任意 URL 交给模型。

## 延迟与资源

分别测量“收消息→桥接唤醒→模型首答→工具排队→TTS/画图/歌声→QQ 发送”，不要只看最终总时长。普通私聊表达完整时允许直接回复；分段消息可以短暂合并，但不能把潜水前几分钟的观察窗口放到每次首答前。

若模型首答慢，检查推理强度、模型选择、重复上下文/工具列表、网络重试；若媒体慢，检查首次模型加载、CPU/GPU 选择、显存竞争和是否重复合成。不要把超时无限放大掩盖死锁。重试必须有次数和耗时上限，同一请求不得重发多份消息。

语音、图像、歌声大模型同时常驻可能耗尽显存。使用 GPU 工作锁/队列，长任务前检查其他任务是否运行；只能在空闲时卸载已完成的模型，不能杀正在生成的用户任务。小显存设备可让轻量 TTS 用 CPU，图像/歌声串行。模型加载和路径缓存均落用户指定盘。

歌声先用真正歌声模型生成有连贯旋律的源唱，再转换目标音色；确认 F0、采样率、声部/伴奏对齐和限幅。测试技术指标通过不代表用户觉得好听，必须交付可播放试听，并单独记录用户听感结果。

## 安全恢复与升级

1. 修改前制作有时间戳的本项目配置/补丁快照。备份含密钥、账号及人设，留在本机受限目录，不随 skill 分发。
2. 停止服务前核对 PID 的可执行文件、参数和工作目录归属。先停桥接，按需要停媒体与网关；不停止未知 DSH/QQ 实例。
3. 使用同版本官方包建立平行新目录，恢复本次用户配置的必要字段，重新应用有记录的适配补丁，运行只读验收，再切换启动器。不要直接覆盖整个生产目录。
4. 保留原有角色/曲库/表情/模型数据；升级若改变 schema，进行字段级迁移并保留回滚副本。账号和 token 必须来自该用户自己的安装。
5. 清理只删除本次明确生成的缓存/临时文件。先解析最终绝对路径并确认在安装根目录内，使用同一 PowerShell 和 `-LiteralPath`，不能将枚举结果拼成 `cmd /c` 删除命令。
6. 回滚恢复已保存的版本、lockfile、适配模块和配置；重启后重新验证文本、权限以及所有已启用媒体模块。报告哪些通过、哪些仍等待用户扫码/试听，不能把部分成功说成完整恢复。

## 上游结构变化的处理

此流程基于实际验证过的架构，不冻结第三方未来 API。若 action、配置字段、preset 注册方式或许可证变化，先读当前官方源码/文档，再更新最小适配和测试。无法验证的能力明确标成待完成；不得虚构安装命令、下载地址、默认音色、现成桌面版或已公开的私人插件。
